# web-chat — ვებ-ჩატი ადმინ პანელით

მარტივი ვებ-ჩატი: მომხმარებლები რეგისტრირდებიან და შედიან **მხოლოდ
username-ით და პაროლით**, მეტი არაფერი. ერთმანეთს username-ით
პოულობენ და ჩატაობენ (1:1 და ჯგუფური ჩატები, თითოეულს თავისი სათაური
აქვს). **ადმინ პანელში ყველა ჩატი თავის სათაურით ჩანს** — წევრებით
და შეტყობინებების რაოდენობით, შიგნით შესვლაც შეიძლება — და ყველა
მომხმარებლის სიაა. მეტი არაფერი.

პირველი დარეგისტრირებული მომხმარებელი ავტომატურად ადმინი ხდება.

ტექნიკა: Cloudflare Worker + D1 — იგივე უფასო მოდელი, რაც
locallink-stock-ს აქვს. ინტერფეისი ერთი თვითკმარი HTML გვერდია,
მუქი თემა, ქართული.

## როგორ მუშაობს

- **რეგისტრაცია / შესვლა** — მხოლოდ username (3–30 სიმბოლო, მხოლოდ
  ლათინური ასოები, ციფრები და `_`) და პაროლი (მინიმუმ 4 სიმბოლო).
  სხვა არაფერი არ ითხოვება და არსად ინახება.
- **მომხმარებლის ძებნა** — username-ის დასაწყისით; ძებნის შედეგიდან
  „ჩატის დაწყება" ქმნის 1:1 ჩატს (თუ უკვე არსებობს, იმას ხსნის).
- **ახალი ჯგუფი** — სათაური + წევრების username-ები მძიმით.
- **ჩატები** — სია სათაურით, ბოლო შეტყობინებით და წაუკითხავის
  რაოდენობით; შეტყობინებები 5 წამში ერთხელ ახლდება თავისით.
- **ადმინი** — „ადმინი" ღილაკი მხოლოდ ადმინს უჩანს: ყველა ჩატი
  სათაურით + წევრები + შეტყობინებების რაოდენობა + „შესვლა" (ნებისმიერი
  ჩატის წაკითხვა), და ყველა მომხმარებლის სია.

## დაყენება (Cloudflare dashboard, ტერმინალი არ სჭირდება)

1. **GitHub რეპო:** GitHub-ზე შექმენი ახალი საჯარო რეპო, მაგ.
   `web-chat`, და ატვირთე ამ საქაღალდის შიგთავსი (`wrangler.toml`,
   `src/`, `schema.sql`, `README.md`). GitHub App-ს რეპოს შექმნა
   არ შეუძლია — ეს ნაბიჯი შენია (ბრაუზერში, 2 წუთი).
2. **D1 ბაზა:** Cloudflare dashboard → Workers & Pages → D1 (Storage)
   → Create database, სახელი `web-chat-db`. დააკოპირე მისი
   `database_id` და ჩასვი `wrangler.toml`-ში
   `REPLACE_WITH_YOUR_D1_DATABASE_ID`-ის ადგილას.
3. **Worker:** Workers & Pages → Create → Connect to Git → ეს რეპო.
   Worker-ის სახელი `web-chat` — მისამართი იქნება
   `https://web-chat.<ანგარიში>.workers.dev`.
4. **საიდუმლოება** (Worker → Settings → Variables and Secrets):
   - `SESSION_SECRET` — გრძელი შემთხვევითი სტრიქონი (ნებისმიერი,
     მაგ. 64 შემთხვევითი სიმბოლო). სხვა საიდუმლო არ არის —
     ადმინის პაროლი ცალკე არ არსებობს: პირველი დარეგისტრირებული
     მომხმარებელი ადმინი ხდება.
   - მნიშვნელობა არასდროს ჩაწერო ჩატში ან რეპოში.
5. **Deploy.** Worker-ი პირველივე მოთხოვნაზე თვითონ ქმნის D1
   ცხრილებს (lazy idempotent სქემა v1..v3) — მიგრაციების გაშვება
   არ სჭირდება.
6. **შემოწმება:** გახსენი `https://web-chat.<ანგარიში>.workers.dev`,
   დარეგისტრირდი პირველი (შენ ადმინი გახდები — „ადმინი" ღილაკი
   გაჩნდება), მერე მეორე მომხმარებლით (მაგ. ტელეფონიდან) დარეგისტრირდი
   და ორივე მხრიდან გაცვალეთ შეტყობინებები.

## API

| მეთოდი | გზა | აღწერა |
|---|---|---|
| `GET` | `/` | ჩატის გვერდი (ერთი თვითკმარი HTML) |
| `GET` | `/api/health` | სტატუსი: `{ok, service}` |
| `POST` | `/api/register` | `{username, password}` → session cookie (30 დღე); პირველი მომხმარებელი = ადმინი; ლიმიტი 5/წთ ერთ IP-ზე |
| `POST` | `/api/login` | `{username, password}` → session cookie; არასწორი username თუ პაროლი — ერთი და იგივე ზოგადი პასუხი; ლიმიტი 5/წთ ერთ IP-ზე |
| `POST` | `/api/logout` | სესიის წაშლა |
| `GET` | `/api/me` | `{username, is_admin}` თუ შესულია (auth საჭიროა) |
| `GET` | `/api/users/search?q=` | username-ის პრეფიქსით ძებნა, საკუთარი თავის გარეშე, მაქს. 20 (auth საჭიროა) |
| `POST` | `/api/chats` | `{type:'direct', username}` — 1:1 ჩატი (არსებული ბრუნდება) ან `{type:'group', title, members:[username...]}` — ჯგუფური (auth საჭიროა) |
| `GET` | `/api/chats` | ჩემი ჩატები: სათაური, წევრები, ბოლო შეტყობინება, წაუკითხავი (auth საჭიროა) |
| `GET` | `/api/chats/:id/messages` | შეტყობინებები (ბოლო 50), ან `?after=<id>` — მხოლოდ უფრო ახლები; კითხვა წაკითხულად ნიშნავს (auth + წევრობა საჭიროა) |
| `POST` | `/api/chats/:id/messages` | `{body}` — 1–2000 სიმბოლო (auth + წევრობა საჭიროა); ლიმიტი 60/წთ ერთ IP-ზე |
| `GET` | `/api/admin/overview` | ყველა ჩატი სათაურით + წევრები + შეტყობინებების რაოდენობა, და ყველა მომხმარებელი (მხოლოდ ადმინი) |
| `GET` | `/api/admin/chats/:id/messages` | ნებისმიერი ჩატის შეტყობინებები (მხოლოდ ადმინი) |

## უსაფრთხოება

- პაროლი: PBKDF2-SHA256, 100 000 იტერაცია, თითო მომხმარებელზე
  ცალკე შემთხვევითი მარილი; ბაზაში მხოლოდ hash ინახება
  (`pbkdf2$100000$<მარილი>$<hash>`), უბრალო ტექსტი არსად.
- სესია: შემთხვევითი ტოკენი, ბაზაში მხოლოდ SHA-256 hash ინახება
  (SESSION_SECRET-ით); cookie არის HttpOnly + Secure + SameSite=Lax,
  30 დღე.
- Rate limiting IP-hash-ით (დღიური მარილით) — ნედლი IP არსად ინახება.
- მუტაციური API-ები ამოწმებენ `Origin`-ს (მხოლოდ იმავე ჰოსტი).
- საიდუმლოებები მხოლოდ env ცვლადებში — კოდში და რეპოში არაფერია.
- ჩატში შესვლა მხოლოდ წევრებს შეუძლიათ; ადმინის ხედვა მხოლოდ ადმინს.

უარყოფა, username-ის ვალიდაცია), **პაროლის hash-ის შემოწმება** (არ არის
უბრალო ტექსტი, `pbkdf2$100000$` ფორმატი, ერთი და იგივე პაროლი სხვადასხვა
მარილით = სხვადასხვა hash), ლოგინი (არასწორი პაროლი/username — ერთი
ზოგადი პასუხი, სწორი = cookie HttpOnly + Secure + SameSite=Lax),
ძებნა, ჩატის შექმნა (1:1 დუბლიკატი იგივე ჩატს აბრუნებს, ჯგუფი
სათაურით), ჩატების სია (სათაური თითოეული მხარისთვის მეორე წევრის
username-ია, წაუკითხავი), შეტყობინებები (გაგზავნა/კითხვა, `after=`
polling, წევრობის შემოწმება, ვალიდაცია), ადმინის მიმოხილვა (ყველა ჩატი
სათაურით + რაოდენობები, ყველა მომხმარებელი, არა-ადმინის უარყოფა),
logout, Origin-ის შემოწმება, rate limit-ები, inline script-ის
ჰიგიენა (backtick/`${}` არ არის). ტესტის საიდუმლო მხოლოდ ტესტისთვისაა
და არ გამოიყენება production-ში.
